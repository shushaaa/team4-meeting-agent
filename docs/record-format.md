# 업무 기록 형식

`records/<record_id>.md` 한 파일을 기록과 검증 단계가 함께 사용합니다.

## 헤더

```yaml
record_id: WORK-YYYYMMDD-NNN
record_status: COMPLETE | FAIL
verification_status: PENDING | VERIFIED | FAIL
source_file: 상대 경로
updated_at: YYYY-MM-DD HH:mm
```

## 본문

| 항목 | 내용 | 상태 | 근거 |
| --- | --- | --- | --- |
| 프로젝트명 |  | 확인/미확인 |  |
| 기간 |  | 확인/미확인 |  |
| 배경·문제 |  | 확인/미확인 |  |
| 본인 역할 |  | 확인/미확인 |  |
| 행동·의사결정 |  | 확인/미확인 |  |
| 협업 대상 |  | 확인/미확인 |  |
| 결과·성과 |  | 확인/미확인 |  |
| 수치 근거 |  | 확인/미확인 |  |
| 핵심 역량 |  | 확인/미확인 |  |

## 보완 질문

질문은 최대 3개입니다. 답변이 없더라도 파일은 저장하고 검증 단계로 진행합니다.

## 검증 결과

```text
- 확인 항목:
- 미확인 항목:
- 이력서 사용 가능 항목:
- 추가 확인 질문:
```

## 판정 규칙

- `career-record`는 근거 위치만 적고 최종 확인 판정을 하지 않습니다.
- `career-verify`만 항목 상태를 `확인·미확인`으로 확정합니다.
- 원문 또는 명시적 사용자 답변에 있으면 `확인` 후보입니다.
- 수치는 비교 기준과 계산·자료 근거까지 있어야 `확인`입니다.
- 팀 성과와 본인 행동이 구분되지 않으면 `미확인`입니다.
- 해석·추정이 필요한 정보는 모두 `미확인`입니다.
- 미확인 항목은 기본 이력서에 사용하지 않습니다.
